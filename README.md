# Praxis CRM Κλήσεων

Web εφαρμογή για τηλεφωνικές κλήσεις σε υποψήφιους πελάτες κάθε κατηγορίας: λογιστικά, δικηγορικά, ιατρεία, ξενοδοχεία κ.ά.

- **Φιλοξενία:** GitHub Pages. Είναι στατική σελίδα, χωρίς server.
- **Σύνδεση:** με εταιρικό λογαριασμό Microsoft 365.
- **Βάση δεδομένων:** δύο λίστες SharePoint στο site που θα ορίσεις, στο site `https://reinaldogr.sharepoint.com/sites/praxis`, ξεχωριστές από τις λίστες του Tickets:
  - `CRM_Prospects`: οι υποψήφιοι πελάτες, με στοιχεία επικοινωνίας, κατάσταση, σημειώσεις και οικονομικά (ΑΦΜ, ΓΕΜΗ, κύκλος εργασιών, εργαζόμενοι).
  - `CRM_Calls`: το ιστορικό όλων των κλήσεων. Κάθε εγγραφή έχει ποιος κάλεσε, πότε, το αποτέλεσμα και τη σημείωση.

Τα δεδομένα **δεν** μπαίνουν στο GitHub. Μένουν μόνο στο SharePoint σου, με τα δικαιώματα του site.

---

## Βήμα 1 — Καταχώριση εφαρμογής στο Microsoft Entra ID (5′)

1. Άνοιξε το https://entra.microsoft.com → **Applications → App registrations → New registration**.
2. Συμπλήρωσε:
   - **Name:** `Praxis CRM`
   - **Supported account types:** *Accounts in this organizational directory only (Single tenant)*
   - **Redirect URI:** πλατφόρμα **Single-page application (SPA)**, διεύθυνση `https://<github-χρήστης>.github.io/<όνομα-repo>/` (με `/` στο τέλος).
     Για δοκιμή από τον υπολογιστή σου πρόσθεσε και το `http://localhost:8080/`.
3. **API permissions → Add a permission → Microsoft Graph → Delegated** και πρόσθεσε `User.Read` και `Sites.Manage.All`. Μετά πάτα **Grant admin consent**.
4. Από τη σελίδα **Overview** αντίγραψε το **Application (client) ID** και το **Directory (tenant) ID** στο `config.js`.
5. Στο `config.js` γράψε επίσης το `siteUrl`, π.χ. `https://reinaldogr.sharepoint.com/sites/Ticketing`.

> Η εφαρμογή βλέπει ό,τι βλέπει ο χρήστης που συνδέεται και τίποτα παραπάνω. Η γραμματεία χρειάζεται δικαίωμα **Edit (Member)** στο SharePoint site.

## Βήμα 2 — GitHub Pages (5′)

1. Στο GitHub φτιάξε νέο repository, π.χ. `praxis-crm`.
   - Το δωρεάν Pages θέλει public repo. Δεν πειράζει, γιατί στον κώδικα δεν υπάρχουν μυστικά ούτε δεδομένα.
2. Ανέβασε **όλα** τα αρχεία αυτού του φακέλου: `index.html`, `app.js`, `app.css`, `config.js`, `README.md` και τα λογότυπα `praxis-logo.svg`, `praxis-logo-wordmark.svg`, `praxis-x.svg`.
   - **ΜΗΝ** ανεβάσεις το `kentro-metafora.json`.
3. Πήγαινε **Settings → Pages → Build and deployment**, διάλεξε *Deploy from a branch* και μετά `main` και `/ (root)`. Πάτα **Save**.
4. Σε 1–2 λεπτά η εφαρμογή ανοίγει στο `https://<github-χρήστης>.github.io/praxis-crm/`. Η διεύθυνση πρέπει να είναι ίδια με το Redirect URI του βήματος 1.

## Βήμα 3 — Πρώτη εκκίνηση και μεταφορά δεδομένων

1. Άνοιξε τη σελίδα και πάτα **Σύνδεση με Microsoft**.
2. Η εφαρμογή δεν θα βρει τις λίστες. Πάτα **Δημιουργία λιστών** και θα φτιαχτούν με όλες τις στήλες.
3. Πήγαινε **Εισαγωγή**, επίλεξε το `kentro-metafora.json`, πάτα **Έλεγχος αρχείου** και μετά **Εισαγωγή**.
   - Μεταφέρονται οι 421 υποψήφιοι μαζί με τις καταστάσεις, τις σημειώσεις, τις επανακλήσεις και το ιστορικό κλήσεων της παλιάς εφαρμογής.
4. Από εκεί και πέρα σταματάς την παλιά εφαρμογή στο `C:\kentro`, ώστε οι κλήσεις να γίνονται μόνο στη νέα.

## Εισαγωγή νέων υποψηφίων (οποιασδήποτε κατηγορίας)

Από την καρτέλα **Εισαγωγή** ανεβάζεις CSV, π.χ. από Excel με «Αποθήκευση ως CSV UTF-8». Η εφαρμογή αναγνωρίζει τις στήλες:
`Επωνυμία, Κατηγορία, Περιοχή, Διεύθυνση, Νομική μορφή, Υπεύθυνος, Τηλέφωνο, Email, Website, Σημείωση, ΑΦΜ, ΓΕΜΗ, Κύκλος εργασιών, Εργαζόμενοι, Έτος`.
Αν το αρχείο δεν έχει στήλη Κατηγορία, γράφεις την κατηγορία στο πεδίο της φόρμας και εφαρμόζεται σε όλες τις γραμμές.

**Κανόνες:**
- Ένας υποψήφιος θεωρείται ίδιος με υπάρχοντα αν έχει το ίδιο τηλέφωνο. Αν δεν έχει τηλέφωνο, συγκρίνεται με επωνυμία και περιοχή μαζί.
- Στους υπάρχοντες συμπληρώνονται μόνο τα κενά πεδία.
- Καταστάσεις, κλήσεις και σημειώσεις δεν αλλάζουν ποτέ από μια εισαγωγή.

## Οικονομικά στοιχεία

Κάθε υποψήφιος έχει τα πεδία ΑΦΜ, Αρ. ΓΕΜΗ, Κύκλος εργασιών, Εργαζόμενοι, Έτος και Σημειώσεις οικονομικών.

**Πώς συμπληρώνονται τώρα:**
- **Χειροκίνητα:** στο «Στοιχεία / οικονομικά» υπάρχουν κουμπιά για αναζήτηση ΑΦΜ/ΓΕΜΗ και ισολογισμών.
- **Μαζικά:** με CSV που περιέχει αυτές τις στήλες.

**Αυτόματη άντληση (μελλοντικό βήμα):** Μπορεί να γίνει από το Open Data API του ΓΕΜΗ (opendata.businessportal.gr, δωρεάν κλειδί). Επειδή όμως ο browser δεν μπορεί να καλέσει απευθείας το API, θα χρειαστεί ένα Power Automate flow ή μια μικρή Azure Function που να γράφει τα στοιχεία στη λίστα.

## Έλεγχος IT (checklist επίσκεψης)

Καρτέλα **Έλεγχος IT**: πατάς στο πεδίο «Πελάτης / υποψήφιος» και διαλέγεις από τη λίστα του CRM (πρώτα όσοι έχουν ραντεβού ή ενδιαφέρον, ή γράφεις επωνυμία / τηλέφωνο). Επωνυμία, υπεύθυνος και άτομα συμπληρώνονται μόνα τους. Μετά συμπληρώνεις ερωτήσεις, τεχνικό έλεγχο (ΟΚ / Θέμα / Κρίσιμο), ευρήματα και επόμενο βήμα.

**Στην καρτέλα του πελάτη** (Λίστα → πατάς τον πελάτη) η ενότητα «Έλεγχοι IT» δείχνει όλους τους ελέγχους του με ημερομηνία, ποιος τον έκανε και πόσα κρίσιμα βρέθηκαν. Με «Άνοιγμα» ανοίγει ο έλεγχος και με «+ Νέος έλεγχος IT» ξεκινάς νέο.

- **Αποθήκευση:** στη λίστα `CRM_Audits`, που φτιάχνεται μόνη της στην πρώτη αποθήκευση (χρειάζεται δικαίωμα διαχείρισης site, άρα την πρώτη φορά κάν' την εσύ). Κάθε νέος έλεγχος γράφει και μια γραμμή στις σημειώσεις του υποψηφίου.
- **Πρόχειρο:** ό,τι συμπληρώνεις κρατιέται στη συσκευή μέχρι να αποθηκεύσεις.
- **Εκτύπωση / PDF:** μία σελίδα A4 με τα στοιχεία που έχεις βάλει. Το **Κενό για εκτύπωση** βγάζει άδειο φύλλο για συμπλήρωση με το χέρι.
- Παλιότεροι έλεγχοι του ίδιου πελάτη ανοίγουν από το «Έλεγχοι πελάτη» και διορθώνονται.

## Χρήσιμα

- Οι λίστες ανοίγουν και κατευθείαν στο SharePoint. Εκεί μπορείς να φτιάξεις δικές σου προβολές ή να τις συνδέσεις με Power BI / Power Automate, π.χ. για ειδοποίηση όταν κάποιος δείξει ενδιαφέρον.
- Κάθε γραμμή στο SharePoint κρατά ιστορικό εκδόσεων, άρα φαίνεται ποιος άλλαξε τι.
- Όταν καλούν δύο άτομα ταυτόχρονα, κάθε υποψήφιος «κλειδώνει» για 10 λεπτά σε όποιον τον πήρε, ώστε να μην τον καλέσει και ο άλλος.
